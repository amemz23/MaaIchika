# MaaIchika

基于 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 的《世界计划 多彩舞台》
（Project SEKAI，**当前只保证日服**）自动化工具。

**一句话**：把每天重复的领奖励、读剧情、清体力交给机器，你只负责打歌。

> 状态图例：✅ 真机跑通并验证过　🔧 代码写完、链路未完整验证　🚧 还没做
>
> 这里的 ✅ 指 `node tools/run.mjs` 报告的「完成（已验证）」—— 节点链真的落在了
> 验证型终点（主页锚点）上，不是"流程没报错"就算过。

## 它能做什么

### 启动与兜底

| 能力            | 状态 | 说明                                                                                                                     |
| --------------- | ---- | ------------------------------------------------------------------------------------------------------------------------ |
| 启动游戏        | ✅   | 拉起日服 → 按返回键关掉 Google 登录弹窗 → 按需下载追加数据 → 点标题页（会重试）→ 关公告 → 走到主页（实测 39.7s / 39.9s） |
| 回主页          | ✅   | 从任意子页面连点返回箭头，直到看见主页底部导航                                                                           |
| 关公告/通知面板 | ✅   | 认面板右上角 X；同一 X 在「通知列表」面板上只有 0.787 分，阈值按实测定                                                   |
| 等加载          | ✅   | 认右下角初音头像，`[JumpBack]` 轮询等它消失 —— 等画面，不等秒数                                                          |

### 日常奖励

| 能力          | 状态 | 说明                                                                                                                                                                                                     |
| ------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 领礼物        | ✅   | 首页 → 礼物箱 → 有物：一键领取 → 返回；空箱：读到「0件」→ 直接返回。**两个分支都真机闭环过**（先领到、再跑一次读到 0件）                                                                                 |
| 领登录奖励    | ✅   | 认「報酬を獲得しました。」（OCR 实测 1.000 / 主页 MISS），点掉所有奖励页再回主流程（真机 7.0s 通过）                                                                                                     |
| 每日挑战      | 🔧   | 两个「不能打」的状态都验证过：当天已打（「本日分は終了しました。」→ 回主页，11.3s）、当体力为 0（选人→选角→选曲→开自动设置→体力为0→回主页，11.5s）。**能打的那一场还没完整跑过** —— 每次想跑时体力都是 0 |
| 任务/使命奖励 | 🚧   | 优先级最低：UI 层级深，跳过着色未完成条目很啰嗦                                                                                                                                                          |

### 演出（清体力）

| 能力     | 状态 | 说明                                                                                                                                                                                                                                                                                                            |
| -------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 进演出页 | ✅   | 主页 → LIVE → 单人 → 決定，停在编成页，不消耗 Live Bonus（调试 / 手动挑歌用）                                                                                                                                                                                                                                   |
| 收尾结算 | ✅   | 从 LIVE CLEAR 一路点到底：逐页 次へ / OK → 回 LIVE 菜单 → 回主页                                                                                                                                                                                                                                                |
| 单场演出 | ✅   | `任务_演出一场`：主页 → LIVE → 单人 → 決定 → 拖拽开 AUTO → 确认 ON → 开演 → 等打完 → 逐页结算 → 回主页。真机 **183.4s** 全链通过                                                                                                                                                                                |
| 单场清火 | ✅   | `任务_清火`：同上，但改走齿轮「オートライブ回数」→ 決定（实测按完 決定 就会把 AUTO 打开）→ 确认 AUTO → 开演。真机 **187.2s** 全链通过                                                                                                                                                                           |
| 循环清火 | ✅   | 游戏**不会**自己循环（即使设了「ライブボーナスがなくなるまで」也只打一场就回主页），所以由外面驱动：`node tools/run.mjs 任务_清火 --repeat 25`（体力多少就 repeat 多少），或在 MXU 里重复添加同一条任务。真机连跑验证：一场打完 203.7s，体力耗尽后下一轮 **23.4s / 10.9s 优雅结束**（认到 `0/25` 就回主页收尾） |

> 只用游戏内 AUTO，不做任何判定。演出期间唯一做的事是"等结束信号"。
> 结算阶段的「点一下继续」浮层（チャレンジスタンプ / ステージランクUP / プレイヤーランクUP / 剧情解放）
> 都已经统一处理；没枚举到的过渡态由 `公共_点一下` 兜底（它只在结算上下文里出现，不会在演出中空点）。

### 剧情

| 能力           | 状态 | 说明                                                                                                                                                                                                                                          |
| -------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 进入剧情       | ✅   | 主页 → ストーリー → 主/活动故事大卡 → 決定 → 章节列表 → 语音弹窗 → 剧情画面（真机跑通，见下）                                                                                                                                                 |
| 语音弹窗处理   | ✅   | 「ボイスデータをダウンロードしますか」→ 勾「連続で読む」→ 选「ボイスなし」（OCR 实测 0.981）                                                                                                                                                  |
| 未读识别       | ✅   | 红色未读角标的 HSV 区间实测 RGB≈255,71,129；ROI 只框章节行 `[640,150,640,450]`：**有未读 count 290 / 已读完 MISS**（旧 ROI 把列表顶部那条红色也框进去，已读完时 count 300 误命中）。找到就**直接点角标本身**（角标在那一行上，点它=点这一行） |
| 连点推进       | ✅   | 三个锚点兜底：右上角 ⋯（对白画面 0.93+）、右下角 AUTO 文字、纯黑边（旁白画面，实测 104000 px 全黑）                                                                                                                                           |
| 读到没未读为止 | ✅   | 分支点在 `故事_本集结束`（认章节列表）：有未读 → `故事_选未读` 命中，点开下一话继续读；没有未读 → `故事_无未读` → 回主页收尾。**真机验证：从有未读的章节列表跑，点开第1話并进入剧情播放**                                                     |

| 读支线故事 | 🔧 | `任务_读支线`：主页 → ストーリー → サイドストーリー 大卡（OCR「サイド」0.996）→ 角色选择页（「キャラクターを選択」0.992）→ 支线列表 → 点第一个「前編」。⚠️ 支线按钮**需要对应卡牌解锁**，本账号初音ミク的支线全部带锁、一张都点不开，所以实际行为是「点一下 → 回主页」（真机 10.1s，完成·已验证）。账号解锁后同一条链会自动开读 |

**主线和支线是两条独立任务**（`过剧情` / `读支线`）：剧情首页两张卡同时可见，而 `next` 是候选列表，主卡永远先命中，所以支线必须单开一条链。

> 整链真机跑通过：`任务_过剧情 → 主页_进故事 → 故事_进主线卡 → 故事_决定 → 故事_选未读 → 故事_勾连读 → 故事_选语音 → 故事_连点（持续）`，
> `故事_连点` 稳定命中 ⋯ 锚点（1.000）并持续推进对白，单次连点累计超过 1500 次（跨了不止一集）。
>
> **它会一直读到这一本没有未读章节为止**，然后回主页收尾。所以日常里可以把它当成
> "把主线/活动剧情读干净"的任务来跑。注意它读的是「メイン／イベントストーリー → 決定」
> 默认选中的那一本；要读别的书，先进到那本书的章节列表再单独跑 `故事_本集结束`（它会从当前位置继续读）。
>
> 活动剧情**不加速、不跳过**（跳了就不给水晶），所以只有纯点击。
> ⚠️ **剧情进行中没法退出**：返回键和点击都只会推进对白，⋯ 菜单里没有退出项。
> 这是游戏机制，所以别在剧情播放时启动别的任务。

## 怎么用

### 一、开发用：无头运行（不需要图形界面）

```bash
python tools/device.py fix        # 把设备刷成 16:9（一次即可，重启失效）
python tools/device.py check      # 自检：比例 / 画布 / 方向

node tools/run.mjs 任务_启动            # 跑一个入口
node tools/run.mjs 任务_领礼包 任务_演出一场   # 一次连接跑多个
node tools/run.mjs --list              # 看所有节点
```

输出长这样（每一行都是框架真实的识别结果）：

```text
  [识别] 主页_进礼物箱 HIT [1218,116,62,64] score=1.000
  [识别] 礼物_空 HIT [860,630,200,60] "0件" score=0.999
  next <- 礼物_空: 礼物_返回
  [动作] 礼物_返回 Click ok
----- 任务_领礼包: 完成（已验证） 12.7s
      节点链: 任务_领礼包 -> 主页_进礼物箱 -> 礼物_空 -> 礼物_返回 -> 公共_主页锚点
```

三种结局：**完成（已验证）** / **结束但未验证**（等于没做成）/ **失败**。

### 二、给别人用：MXU

1. 从 [MXU Releases](https://github.com/MaaXYZ/MXU/releases) 下 `mxu.exe` 放进 `install/`
2. 从 [MaaFramework Releases](https://github.com/MaaXYZ/MaaFramework/releases) 下发行包，
   把 `bin/*.dll` 平铺进 `install/maafw/`，`share/MaaAgentBinary/` 整个放进 `install/maafw/MaaAgentBinary/`
3. `python tools/pack.py` 把 `assets/` 同步进 `install/`
4. **以管理员身份**运行 `install/mxu.exe`

改了 pipeline 之后要**完全退出 MXU 再重开**（点"重新加载"不清模板缓存）。

## 为什么要先把设备刷成 16:9

MaaFramework 只按短边等比缩放，**不补偿宽高比**：

| 设备分辨率               | 缩放后画布 | 结果                                     |
| ------------------------ | ---------- | ---------------------------------------- |
| 2560×1440                | 1280×720   | ✅ 正好是坐标基准                        |
| 1080×1920                | 720×1280   | ✅ 竖屏原生设备，游戏横过来还是 1280×720 |
| 2400×3392（1:1.41 平板） | 1018×720   | ❌ 所有坐标与模板一起失效                |

所以 `tools/device.py fix` 把设备临时覆盖成 16:9，跑完 `reset` 还原。
竖屏原生设备要写**竖着**的宽高（`1440x2560`），写反了横屏游戏会被强制竖屏。

## 设计原则

**1. 状态驱动，不猜**

每个动作前必须有识别依据，动作后必须能验证结果。没有"无识别的盲点点击"，
也没有"next 跑空就算成功"—— 任务链必须落在验证型终止节点上。

**2. `next` 是候选列表，不是执行序列**

这是 MaaFramework 最容易把人坑死的地方，本项目用三条约定绕开：

- 等待/弹窗/加载这类公共节点一律 `[JumpBack]` 引用 + `max_hit`，做完回父节点继续判断；
- 导航节点把自己放进 `next`，点击丢了下一轮重点，点成功了画面变了就不再命中；
- 终点用「主页底部导航真的出现了」来验证。

**3. 不用固定延时等动画**

`pre_delay` / `post_delay` 全局置 0。要等就识别"动画结束后才出现的东西"。

**4. 阈值是量出来的，不是猜的**

`tools/score.mjs` 直接用框架自己的 TemplateMatch 给"模板 × 截图"打分，
`tools/analyze_scores.py` 按标签算正负样本分布，`gap < 0.1` 就说明判别力不够、该换模板。
所有阈值都能在 [识别基线](docs/zh_cn/developers/recognition-baseline.md) 里查到出处。

**5. 不碰不可逆的东西**

- 不消耗任何付费货币、不抽卡、不购买
- 不做音游判定，只用游戏内 AUTO
- 活动剧情不加速、不跳过
- 不点「通信開始」（那是上传成绩）

## 已知缺口

按"下一步该做什么"排序：

1. **AUTO 开关是拖拽控件，Maa 的触控通道对它时灵时不灵**（最优先）。已确认的事实：
    - 主机跑 `adb shell input swipe 1060 1330 1240 1330 700`：**能**稳定切换（OFF→ON→OFF）
    - 同一条命令放进 Maa 的 `Shell` 动作：**不生效**
    - Maa 的 `Swipe`、`TouchDown→TouchMove→TouchUp`（含 `pressure:100`）：**时灵时不灵**
    - 编成页齿轮 →「オートライブ回数」→「決定」：**现在走 OCR 定位「決定」（0.930）已比较稳**，
      这是目前默认路径；`演出_确认AUTO` 负责正向验证，拖拽只作兜底
    - 下一次仍可查「Maa 触控通道 vs 主机 adb 的差异」（怀疑 maatouch 会话期间合成 input 被丢弃）

2. **每日挑战的「当天未打」完整一场还没跑完** —— 选人/选角/选曲/开演都单独验证过，
   但每次想跑完整场时当天挑战都已用完（挑战页显示「本日分は終了しました。」）。
   下一轮游戏日重置后即可补验。

3. **任务/使命奖励** 还没接进任务链（登录奖励、礼物箱已接）。

4. **`公共_回主页` 阈值余量偏紧** —— 返回箭头有暗态，实测最低 0.603，阈值 0.80
   （见[识别基线](docs/zh_cn/developers/recognition-baseline.md)）。实践没出问题，但值得留意。

5. **只保证日服** —— OCR 只列了日服写法，图形节点是日服 UI。扩国服/繁中服要补
   `expected` 并在对应客户端上重新实测阈值。

## 已知问题

- **主页会漂到不同区域**（比如漂到「セカイ / スクランブル交差点」），右上角礼物盒样式跟着变，
  `主页_进礼物箱` 曾因此 MISS。现在用**双模板**（`home/gift_icon.png` + `home/gift_icon_school.png`）
  覆盖了两种样式，但换区域仍可能再变 —— 再变就再补一份模板。

- **`任务_领礼包` 偶发「其实回到了主页、但判定失败」**：礼物页有物品时 `礼物_返回` 会连点 3 次
  把 `max_hit` 耗尽、节点链跑空。最近两次真机都是正常通过（7.7s），仍留作观察项。

## 已经摸清、还没接上的机制

- **`オートライブ回数`**（编成页齿轮）能设成「ライブボーナスがなくなるまで」，但**游戏并不会真的
  循环** —— 实测设完之后仍然只打一场就回主页（开演次数 = 1）。所以循环由外面驱动
  （`run.mjs --repeat`）。它旁边有「クリスタルで回復」，**默认不勾选，永远不要勾**。

- **Live Bonus 为 0 时不能开演** —— 编成页播放按钮会变成**灰的、点不动**（模板分数从 1.000 掉到 0.614）。
  所以 `演出_开演` 的阈值定在 **0.90**（只认"点得动"的亮按钮），并由 `公共_体力为0` 走优雅结束。

- **剧情不能中途退出**（返回键只推进对白）。而且勾了「連続で読む」之后，读完一集会直接接下一集，
  中间没有可识别的画面 —— 所以"一集结束"不需要额外处理。

## 目录结构

```text
assets/
├── interface.json              控制器 / 资源包 / 任务入口 / 多语言
├── resource/
│   ├── default_pipeline.json   全局默认：rate_limit / pre_delay / post_delay / 阈值
│   ├── pipeline/               全部节点，一场景一文件
│   ├── image/                  模板图，基准 1280×720
│   └── model/ocr/              PPOCR 模型（不入库，tools/fetch_ocr.py 拉）
└── locales/interface/          界面文案（中/英）

tools/
├── device.py         分辨率 / 截图 / 点击（坐标按 720 传入）
├── crop.py           按 tools/crops.json 裁模板 + 出对照图
├── score.mjs         用框架给模板打分
├── analyze_scores.py 正负样本分析 → 建议阈值（--apply 写回）
├── probe.mjs         单点探针：一张图 + 一份识别参数
├── run.mjs           无头运行器（带"完成（已验证）"判定）
├── report.py         把 debug/run_*.json 汇总成"各任务上次跑成什么样"
├── check_json.py     结构自检（引用 / 占位 / 盲点动作 / 环无出口 / i18n）
├── check_params.py   参数自检（ROI 越界 / 模板存在 / 阈值范围 / ColorMatch 通道）
├── check_interface.mjs  用真实 MaaFramework 加载 interface + 资源包（离线）
├── pack.py           assets -> install
└── fetch_ocr.py      拉 OCR 模型

docs/zh_cn/developers/   开发手册、识别基线
install/                 打包产物（不入库）
```

## 安全边界

- 只模拟人手点击：不修改内存、不注入进程、不改网络请求
- 所有操作都能在游戏界面里手动复现
- 使用自动化可能违反游戏用户协议，**账号风险自负**
