# MaaIchika

基于 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 的《世界计划 多彩舞台》
（Project SEKAI，**当前只保证日服**）自动化工具。

**一句话**：把每天重复的领奖励、读剧情、清体力交给机器，你只负责打歌。

> 状态图例：✅ 真机跑通并验证过　🔧 代码写完、链路未完整验证　🚧 还没做
>
> 这里的 ✅ 指 `node tools/run.mjs` 报告的「完成（已验证）」—— 节点链真的落在了
> 验证型终点（主页锚点）上，不是"流程没报错"就算过。

## 它能做什么

### 启动与兜底

| 能力            | 状态 | 说明                                                                      |
| --------------- | ---- | ------------------------------------------------------------------------- |
| 启动游戏        | ✅   | 拉起日服、按返回键关掉 Google 登录弹窗、点掉标题页、走到主页（实测 3.3s） |
| 回主页          | ✅   | 从任意子页面连点返回箭头，直到看见主页底部导航                            |
| 关公告/通知面板 | ✅   | 认面板右上角 X；同一 X 在「通知列表」面板上只有 0.787 分，阈值按实测定    |
| 等加载          | ✅   | 认右下角初音头像，`[JumpBack]` 轮询等它消失 —— 等画面，不等秒数           |

### 日常奖励

| 能力          | 状态 | 说明                                                                            |
| ------------- | ---- | ------------------------------------------------------------------------------- |
| 领礼物        | ✅   | 首页 → 礼物箱 → 判空（0件 就返回）→ 一键领取 → 逐页 OK → 返回（空箱实测 12.7s） |
| 领登录奖励    | 🚧   | 「LOGIN BONUS」画面的识别与关闭还没接进任务                                     |
| 每日挑战      | 🚧   | チャレンジライブ，每天一次、不消耗 Live Bonus                                   |
| 任务/使命奖励 | 🚧   | 优先级最低：UI 层级深，跳过着色未完成条目很啰嗦                                 |

### 演出（清体力）

| 能力     | 状态 | 说明                                                                                                                                              |
| -------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 进演出页 | ✅   | 主页 → LIVE → 单人 → 決定，停在编成页，不消耗 Live Bonus（调试 / 手动挑歌用）                                                                     |
| 收尾结算 | ✅   | 从 LIVE CLEAR 一路点到底：逐页 次へ / OK → 回 LIVE 菜单 → 回主页                                                                                  |
| 单场演出 | 🔧   | 各段都单独跑通过（进演出 / 开演（含点击丢失重试）/ 等打完 / 结算 / 回主页），但**还没在同一次任务里从主页连续跑到主页** —— 当时 Live Bonus 已打空 |
| 循环清火 | 🚧   | 上面那条的循环版：按 Live Bonus 或场次上限停                                                                                                      |

> 只用游戏内 AUTO，不做任何判定。演出期间唯一做的事是"等结束信号"。

### 剧情

| 能力       | 状态 | 说明                                                                   |
| ---------- | ---- | ---------------------------------------------------------------------- |
| 自动读剧情 | 🚧   | 下一阶段。活动剧情**不加速不跳过**（跳了就不给水晶），所以是纯点击推进 |

## 怎么用

### 一、开发用：无头运行（不需要图形界面）

```bash
python tools/device.py fix        # 把设备刷成 16:9（一次即可，重启失效）
python tools/device.py check      # 自检：比例 / 画布 / 方向

node tools/run.mjs 任务_启动            # 跑一个入口
node tools/run.mjs 任务_领礼包 任务_演出一场   # 一次连接跑多个
node tools/run.mjs --list              # 看所有节点
```

输出长这样（每一行都是框架真实的识别结果）：

```text
  [识别] 主页_进礼物箱 HIT [1218,116,62,64] score=1.000
  [识别] 礼物_空 HIT [860,630,200,60] "0件" score=0.999
  next <- 礼物_空: 礼物_返回
  [动作] 礼物_返回 Click ok
----- 任务_领礼包: 完成（已验证） 12.7s
      节点链: 任务_领礼包 -> 主页_进礼物箱 -> 礼物_空 -> 礼物_返回 -> 公共_主页锚点
```

三种结局：**完成（已验证）** / **结束但未验证**（等于没做成）/ **失败**。

### 二、给别人用：MXU

1. 从 [MXU Releases](https://github.com/MaaXYZ/MXU/releases) 下 `mxu.exe` 放进 `install/`
2. 从 [MaaFramework Releases](https://github.com/MaaXYZ/MaaFramework/releases) 下发行包，
   把 `bin/*.dll` 平铺进 `install/maafw/`，`share/MaaAgentBinary/` 整个放进 `install/maafw/MaaAgentBinary/`
3. `python tools/pack.py` 把 `assets/` 同步进 `install/`
4. **以管理员身份**运行 `install/mxu.exe`

改了 pipeline 之后要**完全退出 MXU 再重开**（点"重新加载"不清模板缓存）。

## 为什么要先把设备刷成 16:9

MaaFramework 只按短边等比缩放，**不补偿宽高比**：

| 设备分辨率               | 缩放后画布 | 结果                                     |
| ------------------------ | ---------- | ---------------------------------------- |
| 2560×1440                | 1280×720   | ✅ 正好是坐标基准                        |
| 1080×1920                | 720×1280   | ✅ 竖屏原生设备，游戏横过来还是 1280×720 |
| 2400×3392（1:1.41 平板） | 1018×720   | ❌ 所有坐标与模板一起失效                |

所以 `tools/device.py fix` 把设备临时覆盖成 16:9，跑完 `reset` 还原。
竖屏原生设备要写**竖着**的宽高（`1440x2560`），写反了横屏游戏会被强制竖屏。

## 设计原则

**1. 状态驱动，不猜**

每个动作前必须有识别依据，动作后必须能验证结果。没有"无识别的盲点点击"，
也没有"next 跑空就算成功"—— 任务链必须落在验证型终止节点上。

**2. `next` 是候选列表，不是执行序列**

这是 MaaFramework 最容易把人坑死的地方，本项目用三条约定绕开：

- 等待/弹窗/加载这类公共节点一律 `[JumpBack]` 引用 + `max_hit`，做完回父节点继续判断；
- 导航节点把自己放进 `next`，点击丢了下一轮重点，点成功了画面变了就不再命中；
- 终点用「主页底部导航真的出现了」来验证。

**3. 不用固定延时等动画**

`pre_delay` / `post_delay` 全局置 0。要等就识别"动画结束后才出现的东西"。

**4. 阈值是量出来的，不是猜的**

`tools/score.mjs` 直接用框架自己的 TemplateMatch 给"模板 × 截图"打分，
`tools/analyze_scores.py` 按标签算正负样本分布，`gap < 0.1` 就说明判别力不够、该换模板。
所有阈值都能在 [识别基线](docs/zh_cn/developers/recognition-baseline.md) 里查到出处。

**5. 不碰不可逆的东西**

- 不消耗任何付费货币、不抽卡、不购买
- 不做音游判定，只用游戏内 AUTO
- 活动剧情不加速、不跳过
- 不点「通信開始」（那是上传成绩）

## 已知缺口

按"下一步该做什么"排序：

1. **Live Bonus 不足的弹窗没处理** —— 体力为 0 时点开演会弹「ライブボーナスが足りません」，
   现在直接失败（安全：绝不会替你用水晶补）。要做成 `option`，默认拒绝补体力。
2. **登录奖励、每日挑战、任务奖励** 还没接进任务链。
3. **剧情** 完全没写（下一阶段）。
4. **只保证日服** —— OCR 只列了日服写法，图形节点是日服 UI。扩国服/繁中服要补
   `expected` 并在对应客户端上重新实测阈值。
5. **`公共_回主页` 阈值余量偏紧** —— 返回箭头有暗态，实测最低 0.603，阈值 0.80
   （见[识别基线](docs/zh_cn/developers/recognition-baseline.md)）。实践没出问题，但值得留意。

## 目录结构

```text
assets/
├── interface.json              控制器 / 资源包 / 任务入口 / 多语言
├── resource/
│   ├── default_pipeline.json   全局默认：rate_limit / pre_delay / post_delay / 阈值
│   ├── pipeline/               全部节点，一场景一文件
│   ├── image/                  模板图，基准 1280×720
│   └── model/ocr/              PPOCR 模型（不入库，tools/fetch_ocr.py 拉）
└── locales/interface/          界面文案（中/英）

tools/
├── device.py         分辨率 / 截图 / 点击（坐标按 720 传入）
├── crop.py           按 tools/crops.json 裁模板 + 出对照图
├── score.mjs         用框架给模板打分
├── analyze_scores.py 正负样本分析 → 建议阈值（--apply 写回）
├── probe.mjs         单点探针：一张图 + 一份识别参数
├── run.mjs           无头运行器（带"完成（已验证）"判定）
├── check_json.py     结构自检（引用 / 占位 / 环无出口 / i18n）
├── pack.py           assets -> install
└── fetch_ocr.py      拉 OCR 模型

docs/zh_cn/developers/   开发手册、识别基线
install/                 打包产物（不入库）
```

## 安全边界

- 只模拟人手点击：不修改内存、不注入进程、不改网络请求
- 所有操作都能在游戏界面里手动复现
- 使用自动化可能违反游戏用户协议，**账号风险自负**
